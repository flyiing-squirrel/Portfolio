# 금융소외계층을 위한 맞춤형 보험 추천

> 건강·생활정보로 조사 시점의 질병 유병 여부를 분류하고, 결과를 보험 상품 탐색에 연결했습니다. 팀장으로서 모델 개발 전반을 맡았습니다.

| 데이터 | 국민건강영양조사 2022·2023년 결합 자료, 13,194개 관측치·675개 변수 |
| 모델 입력·출력 | 건강·생활정보 입력, 질병별 유병 여부 9개 이진 분류 |

| 주요 방법 | MICE 결측치 대체, RandomUnderSampler, SMOTE, RandomizedSearchCV, AUC·F1·F2 평가 |
| 팀 결과물 | 질병 분류 모델과 FastAPI·MySQL 기반 보험 추천 웹 프로토타입 |

## 1. 문제와 목표

보험 상품을 탐색하려면 복잡한 약관과 상품 조건을 이해하고 자신의 상황과 연결해야 합니다. 팀은 금융소외계층이 건강·생활정보를 입력해 관련 보험을 탐색하고, 추천 이유와 약관 설명을 확인할 수 있는 서비스를 제안했습니다.

제가 맡은 모델의 목표는 건강·생활정보로 조사 시점의 질병 유병 여부를 분류하는 것이었습니다. 데이터 전처리와 변수 선택부터 질병별 학습·평가, 최종 모델 선정까지 수행했습니다.

## 2. 담당 역할

| 담당 업무 | 수행 내용 |
| --- | --- |
| 모델 개발 전반 | 팀장으로서 데이터 준비부터 최종 모델 선정까지 모델링 과정 담당 |
| 데이터 전처리 | 2022·2023년 조사 자료 결합, 응답 코드 정리, 결측값 처리와 클래스 불균형 대응 |
| 입력변수 설계 | PCA·상관관계·직접 선택 방식을 검토하고, 건강·생활정보를 입력변수로 구성 |
| 학습과 튜닝 | 질병별로 네 모델을 비교하고 RandomizedSearchCV로 하이퍼파라미터 탐색 |
| 평가와 해석 | 정확도·AUC·F1·F2 및 주요 변수를 비교하고, 양성 누락을 고려한 최종 모델 선택 |

웹 화면과 백엔드·보험 상품 데이터베이스는 아래에 팀 결과물로 소개합니다.

## 3. 데이터에서 서비스까지

```mermaid
flowchart LR
    A[국민건강영양조사 2022·2023] --> B[응답 코드·결측값 처리]
    B --> C[입력변수 구성]
    C --> D[학습 데이터 불균형 처리]
    D --> E[질병별 모델 비교·튜닝]
    E --> F[최종 Logistic Regression]
    F --> G[관련 보험 조회·설명 프로토타입]
```

**결측값과 응답 코드:** 입력변수의 결측값은 MICE 방식으로 대체하고, 수면시간·흡연·직업 등의 응답 범주를 정리했습니다. 타깃의 결측·모름·무응답을 제거하고 비해당을 질병 없음으로 처리하는 규칙을 적용했습니다.

**클래스 불균형:** 질병별 양성 사례 수의 차이가 커서 정확도만으로 모델을 비교하기 어려웠습니다. 제출 보고서에서는 학습 데이터에 RandomUnderSampler를 적용해 다수 클래스를 소수 클래스의 3배 수준으로 줄인 뒤, SMOTE로 소수 클래스를 보강한 것으로 정리했습니다.

**학습과 평가:** 제출 실험은 학습·테스트를 80:20으로 나누고, 질병마다 별도 모델을 학습하는 방식입니다. 보고서 기준으로 50개 하이퍼파라미터 조합과 5-Fold 교차검증을 사용했습니다. AUC와 함께 재현율에 더 큰 비중을 두는 F2를 중점적으로 비교해 Logistic Regression을 최종 선택했습니다.

## 4. 모델 비교와 결과

### 고혈압 분류에서의 모델 비교

| 모델 | 정확도 | AUC | F1 | F2 |
| --- | --- | --- | --- | --- |
| XGBoost | 0.8262 | 0.8848 | 0.6250 | 0.6178 |
| TabNet | 0.7719 | 0.8596 | 0.6226 | 0.7163 |
| LightGBM | 0.8237 | 0.8835 | 0.6237 | 0.6205 |
| **Logistic Regression** | **0.7903** | **0.8906** | **0.6578** | **0.7626** |

고혈압에서는 정확도가 가장 높은 모델과 F2가 가장 높은 모델이 달랐습니다. 정확도 하나를 기준으로 선택하기보다, 양성 누락을 중요하게 보는 평가 목적에 맞춰 판단했습니다.

### 최종 Logistic Regression의 질병별 성능

| 질병 | AUC | F1 | F2 |
| --- | --- | --- | --- |
| 고혈압 | 0.8906 | 0.6578 | 0.7626 |
| 이상지질혈증 | 0.8223 | 0.5443 | 0.6689 |
| 당뇨병 | 0.8520 | 0.3707 | 0.5531 |
| 천식 | 0.6043 | 0.0710 | 0.1491 |
| 아토피 | 0.7408 | 0.1270 | 0.2527 |
| 비염 | 0.6255 | 0.2812 | 0.4024 |
| 부비동염 | 0.6031 | 0.1542 | 0.2752 |
| 중이염 | 0.5851 | 0.1262 | 0.2331 |
| 신장질환 | 0.6155 | 0.0564 | 0.1234 |

고혈압·이상지질혈증·당뇨병에 비해 다른 질병의 F2는 낮았습니다. 9개 질병 모두에서 같은 수준의 성능을 확보한 결과로 해석하지 않습니다.

## 5. 팀 결과물과 배운 점

팀은 HTML·CSS·JavaScript 화면, FastAPI 백엔드, MySQL 데이터베이스를 연결한 로컬 웹 프로토타입을 구현했습니다. 모델이 분류한 질병과 연관된 보험을 조회해 두 상품을 표시하고, AI로 추천 이유를 생성한 뒤 대표 약관의 쉬운 설명을 함께 제공하는 흐름입니다.

프로토타입은 조회된 상품 중 두 개를 무작위로 선택합니다. 질병 분류 결과와 보험 탐색 화면을 연계했지만, 상품 적합성을 학습해 순위를 매기는 추천 모델은 구현하지 않았습니다.

클래스 불균형 상황에서 평가 목적에 맞는 지표로 모델을 선택했습니다. 질병별 성능 차이와 분류 성능·서비스 추천 품질의 차이를 함께 확인했습니다.
