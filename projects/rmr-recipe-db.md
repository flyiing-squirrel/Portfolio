## 1. 문제와 목표

RMR(Restaurant Meal Replacement, 레스토랑 간편식)의 대체 레시피를 연구하려면 서로 다른 레시피의 재료와 사용량을 비교할 수 있어야 합니다. 그러나 비정형 레시피에는 같은 재료를 다르게 적은 이름과 서로 다른 계량 단위가 섞여 있습니다.

기존에 수집된 레시피 17만 건을 정제하고 데이터베이스로 구축했습니다. 이 데이터 기반을 활용한 공통 맛 특성 분석과 대체 레시피 도출은 상위 사업의 목표였습니다.

## 2. 내가 맡은 일

| 담당 업무 | 수행 내용 | 데이터 활용에 필요한 이유 |
| --- | --- | --- |
| 식재료·양념 분리 | 레시피의 재료를 식재료와 양념으로 구분 | 용도에 따른 재료 비교와 분석 기반 마련 |
| 계량 단위 표준화 | 서로 다른 사용량 표현을 g 기준으로 표준화 | 레시피 간 재료 사용량 비교 |
| 재료명 매핑 | 문장 임베딩과 코사인 유사도 임계값으로 불규칙한 재료명을 국가 식품 표준 명칭에 대응 | 같은 재료가 다른 표현으로 분산되는 문제 정리 |

제가 맡은 전처리와 재료명 표준화를 포함해, 팀은 정제된 레시피 데이터를 AWS RDS(MySQL)에 배포했습니다.

## 3. 정제에서 데이터베이스까지

```mermaid
flowchart LR
    A[비정형 레시피 17만 건] --> B[식재료·양념 분리]
    B --> C[계량 단위 표준화]
    C --> D[임베딩 기반 재료명 매핑]
    D --> E[표준 레시피 데이터베이스]
    E --> F[AWS RDS MySQL 배포]
```

재료명이 서로 다른 문자열로 적혀 있어도 같은 대상을 가리킬 수 있습니다. 이 문제에 문장 임베딩을 적용하고 코사인 유사도 임계값을 사용해 표준 명칭과의 매핑을 수행했습니다.

재료명과 함께 사용량의 기준을 맞춰 레시피 간 비교와 식품 데이터 분석에 활용할 수 있는 구조를 마련했습니다.

## 4. 결과와 활용 범위

**비정형 레시피의 표준화에 참여했고, 팀은 결과 데이터베이스를 AWS RDS(MySQL)에 배포했습니다.**

이 데이터베이스는 원재료와 사용량을 일관된 기준으로 관리하고, 향후 공통 맛 모듈 및 대체 레시피 알고리즘 연구를 위한 데이터 기반으로 활용하는 것을 목적으로 구축했습니다.

프로젝트 기록에는 재료 분류, 단위 분리, 재료명 통일, 데이터베이스 생성으로 이어지는 작업 과정이 남아 있습니다.

## 5. 데이터 분석 관점에서의 의미

**재료의 의미와 계량 기준을 일치시켜** 레시피 간 비교가 가능하도록 데이터를 정리했습니다.

문자열의 형태, 재료의 의미, 계량 기준을 함께 고려하는 전처리 경험을 쌓았고, 이를 서비스 연구에 활용할 수 있는 데이터베이스 구축 과정과 연결했습니다.
